1. Start here — what we built

Gujarat has many CCTV cameras. Police need one place to see where cameras are, watch feeds, read number plates, flag stolen vehicles, and hunt a plate across cameras.

Sentinel Command is our thin command layer. We do not replace the government video servers. We consume their catalogue and streams, then add GIS + ANPR + watchlist + hunt.

2. Frontend vs backend (the two programs)

Think of two shops on the same street. The frontend is the shop window the officer looks at. The backend is the storeroom that holds cameras, events, and AI. The window never talks to YOLO directly. It only sends HTTP requests (“please detect Paldi”) and draws whatever JSON comes back.

Frontend = browser UI

Runs in Chrome at port 5174 (Vite + React).

  • Draws the map, list, buttons, video player
  • Has no YOLO, no OpenCV, no password to the RTSP box by itself
  • Calls URLs like /cameras, /hunt?plate=

Backend = Python API

Runs in Uvicorn at port 8000 (FastAPI).

  • Talks to cctv.corp8.cloud with the grid password cookie
  • Opens RTSP with OpenCV, runs YOLO + RapidOCR
  • Reads/writes data/cameras.json, events.json, watchlist.json

Port = a numbered door on your computer. Browser → door 5174. Python → door 8000. They are two processes. They only meet through HTTP.

3. How frontend and backend communicate

The UI never uses a special “React-to-Python cable”. It uses the same web protocol as any website: HTTP. A REST API means “URLs that mean actions”: GET = read, POST = do/create, DELETE = remove. Data is almost always JSON (text that looks like {"cameras": [...]}).

Vite proxy (why we do not type :8000 in the UI)

In frontend/vite.config.js we say: “if the browser asks for /cameras, secretly forward it to http://127.0.0.1:8000”. So React can write fetch("/cameras") and the browser thinks it is talking to the same site (no messy CORS for those paths). CORS in FastAPI is a backup if someone opens the API from another origin.

5. Behind the scenes — fetching all live cameras

We do not walk Gujarat with a spreadsheet of 30 RTSP URLs hard-coded in React. The integrator contract is: start from the catalogue. Camera ids can change.

1
Password. Portal POST /auth/login with the access password. Server sets an HttpOnly cookie named sentinel. Our backend keeps that cookie in a CookieJar (backend/sentinel.py). The browser on localhost cannot use that cookie in an iframe (SameSite=Lax, different site) — that is why we proxy HLS ourselves.
2
Catalogue. GET https://cctv.corp8.cloud/cameras.json returns a JSON array: [{"id":"cam01","name":"01 Chiman bhai Bridge"}, ...] (30 rows). We map cam04 → internal id sentinel-4, guess lat/lng from the name, store in data/cameras.json.
3
Build the three official URLs (from their integrator guide, not guessed forever):
  • HLS (watch / fallback AI): https://cctv.corp8.cloud/cam04/index.m3u8
  • RTSP (AI): rtsp://103.250.160.189:8554/stream/cam04
  • WHEP (low-latency preview, unused in UI): http://103.250.160.189:8889/stream/cam04/whep
4
GIS pins. Leaflet draws a circle per camera. Green = we treat it as online. Hunt draws a red polyline between cameras where that plate was seen.

Fetching the list is cheap. Opening 30 RTSP AI sessions is expensive — each client gets its own copy of the stream. We only capture the camera you click.

6. Video streaming path (watch vs AI)

Two jobs need video, and they use different protocols on purpose.

JobProtocolWhy
Human watching in the dashboard HLS over HTTPS 443, proxied as /live/sentinel-4/index.m3u8, played by hls.js Works through firewalls and Cloudflare. Playlist is AES-128 encrypted; we also proxy enc.key and .ts segments.
Machine ANPR (OpenCV) RTSP over TCP to 103.250.160.189:8554 Integrator’s AI path. Frames have PTS timestamps. UDP would rot on NAT.
Own-feed demo Local MP4 + HTML5 <video> and FFmpeg frame extract Readable close-up plates when government junctions are too far for OCR.

Official HLS playlists are marked EXT-X-PLAYLIST-TYPE:VOD (a looping recording served like live). Their own portal fakes “now” by seeking currentTime = now % duration. Our player does the same jump.

An iframe is a webpage inside a webpage. We used to embed live.corp8.cloud/camera/5. That URL is gone, and cookies would not attach from localhost anyway. So iframe is not how live watch works now. HLS proxy + hls.js is.

7. Capture → annotated JPEG → events → fire alert

flowchart LR A[Click Capture] --> B[OpenCV RTSP TCP or FFmpeg on MP4] B --> C[JPEG stills in data/snapshots/camera_id] C --> D[Click Detect] D --> E[YOLOv8n boxes: car / bike / bus / truck] E --> F[Crop lower part of box] F --> G[RapidOCR reads text] G --> H[events.json row] H --> I{plate in watchlist?} I -->|yes| J[Alert + red banner + beep] I -->|no| K[Normal event list] H --> L[Hunt searches all events]
  1. Capture (live_capture.py / ingest.py): sample about 1 JPEG per second for a few seconds. Stamp IST time on the frame. Store times.json with PTS-based time, not “when the packet arrived”.
  2. Detect (detect.py): YOLOv8n finds vehicles. We do not OCR the whole 1920×1080 image (too noisy). We crop the lower ~45% of the vehicle box — that is where a plate usually sits.
  3. Annotate: YOLO’s result.plot() draws boxes; we overlay plate text. Saved under data/snapshots/{id}/annotated/. Raw JPEGs may be deleted after analyze to save disk.
  4. Normalize plate (plates.py): GJ-01-AB-1234 and gj01ab1234 become GJ01AB1234.
  5. Fire alert (alerts.py): if that string is in watchlist.json, the UI banner says STOLEN PLATE and a short beep plays. Alerts are not a separate database — they are the intersection of events ∩ watchlist.
  6. Hunt: officer types a plate. We scan all events, sort by capture time, pin cameras on the map, export CSV.
Why only cameras 04 and 05 had events earlier: Detect was only run on those two official feeds (plus own MP4s). Importing 30 cameras does not run YOLO on all 30.

Compare: a live RTSP frame is pixels in RAM (OpenCV numpy array, BGR). A JPEG is compressed for disk. HLS .ts is compressed video for the network. YOLO wants pixels (we pass the JPEG decoded back to an array). OCR wants a tight crop, not the whole junction.

10. Glossary — every term you asked about

ANPR

Automatic Number Plate Recognition. Software that finds a vehicle in a picture, then reads the registration text. We split it: YOLO finds the vehicle, RapidOCR reads the crop. Police use it to match stolen / wanted lists without a human staring at every camera.

MediaMTX

An open-source media server that can ingest RTSP and republish as RTSP, HLS, WebRTC, etc. The official Sentinel sandbox behaves like a MediaMTX (or similar) grid. We do not run MediaMTX ourselves. We are a client of theirs. Their hub is why one camera can be watched as HLS in a browser and grabbed as RTSP by OpenCV.

RTSP

Real Time Streaming Protocol. The “live TV cable” language IP cameras have spoken for decades. URL shape: rtsp://host:8554/stream/cam04. There is no rewind file; frames arrive as they are produced (or as the loop plays). We force TCP so NAT/firewalls do not drop pieces and create fake “model bugs”.

FFmpeg

The Swiss-army knife of video. Decode, encode, sample frames, talk RTSP/HLS. We use it to pull JPEGs from MP4s (ingest.py) and OpenCV uses FFmpeg under the hood for RTSP. You rarely see an FFmpeg window — Python calls it.

OpenCV

Open Source Computer Vision library (cv2). It is how we open a stream, read a frame as a grid of pixels, write a JPEG, draw text. It is not the plate reader and not the vehicle detector. It is the hands that hold the image.

YOLOv8n (we use this — not YOLOv9n)

YOLO = You Only Look Once, a family of object detectors. One pass over the image predicts boxes (“there is a car here, confidence 0.91”).

  • v8 = Ultralytics generation we load from yolov8n.pt.
  • n = nano: smallest weights, runs on CPU, good enough for a solo hackathon laptop. Larger letters (s/m/l/x) are more accurate and slower.
  • YOLOv9 is a newer paper/family. We did not switch; v8n is what is in the repo.

We keep classes 2, 3, 5, 7 — car, motorcycle, bus, truck. People/faces are out of scope.

HLS

HTTP Live Streaming (Apple). Video chopped into files a normal HTTPS server can send. A text playlist .m3u8 lists .ts chunks. Browsers on Chrome need hls.js to play it; Safari can play HLS natively. Their playlists are AES-128 encrypted, so the player must also fetch enc.key with the same login cookie (our proxy does that).

iframe

HTML tag that embeds another website. Useful when the other site already has a player. Fragile here: different domain + password cookie + old /camera/id URLs retired. Learning point: iframe ≠ “we integrated the stream”. Real integration is RTSP/HLS with documented URLs.

GIS pins

Geographic Information System points. Each camera has lat and lng. Leaflet (OpenStreetMap tiles) draws a pin. Model 1 of the hackathon is exactly this: a statewide camera registry on a map, even before live video. Hunt then connects pins into a trail.

RapidOCR

Fast on-device OCR (ONNX). After YOLO, we pass the plate-ish crop; RapidOCR returns text + a score. We strip junk characters and regex-match Indian-ish plates. It will fail on distant Paldi-style junctions (letters too few pixels) and succeed on boom-barrier close-ups (our Gate MP4).

TermMeaning here

One-line memory aid

Catalogue (HTTPS JSON) tells us which cameras exist. HLS (HTTPS) is for watching. RTSP (TCP) is for AI. YOLO finds the vehicle. RapidOCR reads the plate. Watchlist decides if we shout. Hunt draws the route on GIS pins.
